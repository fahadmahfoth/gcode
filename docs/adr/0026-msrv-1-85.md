# 0026. Raise the minimum supported Rust version to 1.85

- **Status**: Accepted
- **Date**: 2026-10-03
- **Deciders**: gcode maintainers
- **Relates to**: [0002](0002-rust-single-binary.md), [0009](0009-crates-io-dependencies.md)

## Context

[ADR 0002](0002-rust-single-binary.md) sets the floor at Rust 1.75. Two things
pushed against it:

- `llama-cpp-2`, the binding Phase 1.5 needs, uses `std::sync::LazyLock`, stable
  since 1.80. Building it with 1.75 fails with 24 errors (tried, 2026-10-03).
- `clap` 4.6, `clap_lex` 1.1, and `indexmap` 2.12 already needed newer compilers,
  and the lockfile held them back by hand. `cargo update` undoes that silently.

## Decision

`rust-version` is **1.85**. 1.85 is the first release of edition 2024 and the
floor `clap` 4.6 already declares, so the hand-held pins go away.

This amends one clause of ADR 0002 (the 1.75 floor). Everything else in that ADR
stands: one static binary, musl targets, `panic = "abort"`, and the FFI boundary
that never reaches the classifier.

## Consequences

- The `clap` requirement is `4.5` again; the `clap_lex` and `indexmap` pins are
  removed from `Cargo.toml`.
- The MSRV audit in `docs/TESTING.md` checks against 1.85.
- A machine with a distribution Rust older than 1.85 must use `rustup`.
- 1.85 is from February 2025; it is the oldest toolchain the project tests.
